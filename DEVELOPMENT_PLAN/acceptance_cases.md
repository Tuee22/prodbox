## Execution contract

Run the actual built public binary with an explicit owned configuration and recorded source/binary/image identity. The final scenario registry exposes `prodbox test run phase-NN` as the cumulative set through that phase and `prodbox test run all` as the final aggregate. These are target commands; Phase 1 implements the runner. Phase 0 uses the current build/check entrypoints and its actual checker test group, without depending on that later runner.

Every case records its immutable case ID, public command and arguments, environment/deployment/operation identity, bounded time/resource/spend/cleanup budget, required real dependencies, independent observer, expected outcome, actual outcome, and cleanup disposition. A missing budget, observation, or cleanup result is incomplete. Evidence excludes secret values, unkeyed secret hashes, and raw elevated credential material. A historical run qualifies only the exact implementation/configuration scope it exercised.

Production-policy tests use a separate disposable project anchor and `.data/<id>` owned by the outer test run, not the operator's actual production root. Ordinary test resources remain under `.test-data/<run-id>`. The production-policy path uses the real protected prompt; a harness-owned terminal may supply the test fixture's input through that same prompt. There is no production-bypass flag.

All mutations go through registered prodbox paths. Read-only independent provider diagnostics are permitted. A runner's exit code, rendered manifest, constructed witness, old receipt, source scan, or fake provider cannot prove real effects. A proxy may drop a real response; it cannot fabricate the observation that licenses cleanup. If a required external account/domain/credential is missing, the owning phase remains incomplete; no later phase substitutes for it.

## Cleanup and evidence closure

Each owning phase supplies the exact resource IDs/families and dependency-ordered cleanup for its cases. A cleanup failure, denied read, ambiguous worker, or missing credential-retirement result keeps the case and phase incomplete. Preserve its operation/run ID and required evidence; never hide failure by deleting the test root. Test campaign SES reuse is permitted within the campaign's own identity; its final cleanup remains required and cannot use production SES.

Run the corresponding source mutations in [mutation_cases.md](mutation_cases.md) in addition to these unmodified real cases. Source mutants never receive live AWS credentials or certify provider cleanup. A live run requiring a hand action remains diagnostic evidence and does not close a case. The manual AWS cleanup recorded before documentation adoption is a starting observation, not acceptance evidence for the future implementation.
